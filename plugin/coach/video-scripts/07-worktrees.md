# Video 7 — Each chat gets its own copy of the code (about 2 minutes)

**On screen:** the desktop app's sidebar with two chats, each showing a different branch name.

This one's for builder folders, where Claude writes code.

In a builder folder, every chat works on **its own copy** of your project. The tech word is
"worktree," but think of it as a photocopy Claude can scribble on. Changes stay on that copy
until you say **wind down**. Then they get added to the main version.

Why bother? Two reasons. You can have two chats building different things at the same time
without stepping on each other. And if one goes sideways, your main version is safe.

Here's the order of a typical job:
1. Talk it through.
2. Claude builds it and tests it on your computer.
3. You try it.
4. Wind down, and it joins the main version.
5. You say yes to a "push," and it goes live.

Nothing goes live without that yes. Claude will tell you exactly what the push carries before it
asks.

Once you've done this a few times and you're comfortable, there's a power move: **autopilot
dev.** After you've talked a feature through, those two words tell Claude to build it, test it,
and hand it to you to try, without asking you anything else. Give it a few weeks first.
